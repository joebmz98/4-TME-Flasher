Requirements: Chrome or Edge on a computer (WebUSB is not available in Firefox, Safari or on phones). On Windows the bootloader may need a one time driver change, see Troubleshooting below.

How to flash

  1. Connect the Daisy Seed's micro‑USB port straight to the computer (not a hub) with a data cable.
  2. Put the Seed into DFU mode: hold BOOT, tap RESET, then let go of BOOT. 4-TME goes silent and the OLED and LEDs stop. With firmware v16 or later running you can skip the buttons: use Restart 4-TME into DFU mode below instead.
  3. Choose the firmware, click Flash Firmware and pick DFU in FS Mode in the popup.
  4. Wait for Done. 4-TME restarts by itself. If it does not, press RESET once. Your presets, settings and last sound are kept: they live in 4-TME's W25Q64 SPI flash, which the flasher never touches.

Running firmware v16 or later? Skip the buttons:

Pick 4-TME's USB serial port in the popup. It restarts as DFU in FS Mode, ready to flash.

Troubleshooting

DFU in FS Mode is not in the list

The Seed is not in DFU mode yet. Repeat step 2, try a different cable (many micro‑USB cables are charge only) and plug straight into the computer. On Windows, Device Manager shows DFU in FS Mode while it is in DFU mode.

Windows: "Access denied" or "Unable to claim interface"

Chrome can only talk to the bootloader through the WinUSB driver. Download Zadig, put the Seed in DFU mode, choose Options > List All Devices, select DFU in FS Mode, pick WinUSB and click Replace Driver. This is needed once per computer.

Linux: the device appears but cannot be opened

Add a udev rule so your user can access it, for example SUBSYSTEM=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="df11", MODE="0666" in /etc/udev/rules.d/50-stm32-dfu.rules, then unplug and replug the Seed.

"Built for the Daisy bootloader" or "will not fit"

The ROM bootloader this page talks to writes the Seed's 128 KB internal flash only. Build for internal flash (the default for the Daisy Seed board in the Arduino IDE). If the build is too big, use Tools > Optimize > Faster (-O2) with LTO: 4-TME v16 with USB support set to CDC is about 120 KB that way.

It flashed, but the editor can't find 4-TME

The editor talks to 4-TME over its USB port as a serial port, which only exists when the firmware was built with Tools > USB support > CDC (generic 'Serial' supersede U(S)ART). The release firmware on this site is built that way.

It flashed, but 4-TME does not start

Press RESET, or unplug and replug. If it still does not start, click Download Log and send it over.

Warnings about "A transfer error has occurred"

The flasher resends any piece that fails in smaller parts and checks the result byte by byte, so a few warnings in the log are normal. ?block=256 on the page address forces small transfers from the start.
